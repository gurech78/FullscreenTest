2. Element-Fullscreen (element.requestFullscreen())

Funktioniert auf Desktop-Safari und iPad. Auf dem iPhone ist die API für normale Elemente nicht verfügbar – der Button zeigt, was passiert.

Ich will Vollbild!
normaler Modus

Versucht screen.orientation.lock('landscape') (benötigt in der Regel echten Fullscreen). Gelingt das nicht – wie auf dem iPhone –, wird das Element im Hochformat per CSS um 90° gedreht.

3. Video-Fullscreen (video.webkitEnterFullscreen())

Der einzige Weg zu echtem Vollbild auf dem iPhone: der native iOS-Videoplayer.

Hintergrund

    

      • iPhone (iOS Safari): document.fullscreenEnabled ist false, Element.prototype.requestFullscreen
      fehlt bzw. tut nichts. Ausnahme: <video> über webkitEnterFullscreen() (native Player-UI, keine eigene HTML-UI möglich).

      • iPad (iPadOS ≥ 12): webkitRequestFullscreen(), ab 16.4 auch ungeprefixt requestFullscreen().

      • Alternative auf dem iPhone: Pseudo-Fullscreen per CSS (position:fixed; height:100dvh) oder die Seite
      via „Zum Home-Bildschirm“ als Web-App starten (display-mode: standalone – ganz ohne Safari-Leisten).

      • Querformat erzwingen: screen.orientation.lock() funktioniert nur auf Android (Chrome) im Fullscreen; Safari/iOS unterstützt es nicht.
      Auf dem iPhone bleibt nur das Drehen per CSS (transform: rotate(90deg)) oder ein Hinweis „Bitte Gerät drehen“.

      • Alle Fullscreen-Aufrufe müssen aus einer Benutzer-Geste (z. B. click) heraus erfolgen.
